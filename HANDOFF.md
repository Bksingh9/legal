## Compliance non-negotiables

1. **BCI Rule 36** — no public lawyer profiles. Names, photos,
   testimonials, public ratings tied to identity are all banned.
   Lawyers are matched by `(anon_slug, specialization, languages,
   state, years_exp, rating)` only.
2. **DPDP Act 2023** — consent at point of collection (every public
   form has the `<ConsentCheckbox />`), audit-trail of accepted
   policy version (`consultation_leads.consent_policy_version`,
   `lawyer_applications.consent_policy_version`), data residency
   `ap-south-1`, right-to-export / right-to-erase via `/account` +
   `/api/dpdp/*`.
3. **Recording consent** — both parties must consent before
   `/api/consultations/[id]/start` activates a recording.
4. **Disclaimer** — "Generated by LegalDesk AI. Not legal advice."
   ships on every AI output and on the landing footer.

## What's already shipped (Phases 1–6)

### Tier 1 — AI triage
- Public `/triage` with browser-side Web Speech (Hindi + English),
  optional server STT via Sarvam (`/api/triage/transcribe`)
- `/api/triage/classify` + `/api/triage/prep` both public, gracefully
  use the deterministic local LLM provider at Tier 0
- Real PDF case-prep generation via `@react-pdf/renderer` + Supabase
  Storage upload

### Tier 2 — Document automation (7 SKUs)
- `legal-notice` ₹499, `reply-legal-notice` ₹699, `rent-agreement-11m`
  ₹399, `consumer-complaint-ncdrc` ₹599, `rti-application` ₹199,
  `cheque-bounce-s138` ₹699, `employment-nda` ₹599
- `/documents/[sku]` is **public**; users fill form → preview →
  download free PDF/DOCX without signup
- `WhatsAppShare` button on download success
- Optional `+₹499` lawyer-review add-on (gated on signup + payment)

### Tier 3 — Consultations
- `/talk-to-lawyer` is the Vakilsearch-pattern fast intake (name,
  phone, 1-line issue → admin sees lead live)
- `/consult` for authed clients to book p15/p30/p60 packs
- Match algorithm in `lib/match/lawyers.ts` (top 3 by load + rating)
- Realtime fanout to matched lawyers; offer accept/decline; consent
  gate before start; Jitsi public-meet room as the Tier-0 A/V channel
  (or HMS when keys are set); finish → 24h-hold → Razorpay Route
  payout (or UPI VPA at Tier 0)

### Tier 4 — Plus subscription
- `/pricing` ₹999/year via Razorpay Subscriptions
- Daily cron `/api/cron/subscriptions` mirrors Razorpay state into
  the local `subscriptions` table

### Lawyer onboarding
- Public `/for-lawyers` recruitment landing
- Public `/lawyer/apply` — anonymous submissions provision the auth
  user + send a magic link via Supabase's built-in mailer
- KYC fields: bar council, specs, languages, hours, availability,
  PAN (mandatory for Razorpay Route), optional GSTIN, UPI VPA or
  bank a/c + IFSC for payouts
- Admin verifies in `/admin/lawyers`; suspends similarly
- `notifyMany` fanout on application → admins; `notifyUser` on
  verify/suspend → lawyer

### Auth — three modes
- `/auth/login` tabs: **Continue with Google** + Magic link + Email
  + password
- `/auth/signup` mirror with password creation
- `/auth/forgot-password` + `/auth/reset-password`
- `/account` `<PasswordCard />` to set/change password without
  losing linked identities
- Supabase SSR cookie format; `handle_new_auth_user` trigger
  (migration 0008/0014) auto-creates `public.users` row + welcome
  notification + admin grant in `user_role_grants`

### Real-time (zero-key)
- Supabase Realtime postgres_changes subscriptions on
  `notifications`, `consultations`, `consultation_offers`,
  `consultation_leads`
- Web Push (VAPID, self-generated keypair — not a paid API)
- PWA installable; `public/sw.js` handles push + click-to-focus

### Compliance pages
- `/privacy`, `/terms`, `/refunds-cancellation`, `/grievance`,
  `/about` — DPDP §10 / IT Rules 2021 / Consumer Protection Act
  surfaces. Placeholders `[Name TBD]` are intentional until the
  legal entity is incorporated.

### Production-grade hardening (Phase 6)
- **Rate limiting** via migration 0012/0013: per-IP buckets on
  every public POST (20/min on lead intake, 60/min on triage, etc.).
  Bypass header for the test suite.
- **CSP + security headers**: full Content-Security-Policy in
  `next.config.mjs`, HSTS 2y, X-Frame-Options DENY, Permissions-Policy
  scoping camera/mic to Jitsi only.
- **Sentry**: `sentry.{client,server,edge}.config.ts` +
  `instrumentation.ts`. No-op without DSN; drop the env vars in to
  activate.
- **PostHog**: `lib/analytics/{posthog,posthog-node}.ts`. No-op
  without the public key. First server event wired: `lead.submitted`.
- **OpenAPI**: `lib/openapi/spec.ts` builds the spec; `/api/openapi`
  serves JSON; `/api/docs` renders RapiDoc (loaded from a CDN
  allowlisted in CSP).
- **A11y**: `tests/e2e/journey-a11y.spec.ts` axe-core baseline on
  8 public pages, WCAG 2.1 AA.
- **CI**: prod-smoke job runs the full 117-test suite on PR to
  `main` (gracefully skips without secrets). `npm audit` job fails
  on high/critical.
- **Dependabot**: weekly npm + GitHub Actions PRs against the dev
  branch, not main.
- **Cron**: `vercel.json` schedules `/api/cron/subscriptions` daily
  + `/api/payouts/release` daily.

## Recent session deliveries (May 2026 — live on prod)

- **Tier 5 B2B shipped** (was Phase 7). Migration `0015_b2b_orgs.sql`
  applied to prod (organizations / api_keys / org_api_usage + atomic
  `org_usage_consume` quota function). `lib/orgs/` mints sha256-hashed
  Bearer keys (`ldk_live_<prefix>_<secret>`) with scoped permissions
  (`documents:generate`, `notices:bulk`) and constant-time verification.
  Public surface live: `POST /api/v1/documents/generate`,
  `POST /api/v1/legal-notices/bulk` (per-org rate-limited via
  `rateLimitByKey`). Admin UI at `/admin/orgs`. Plans: starter ₹4,999
  (100 docs/mo), growth ₹9,999 (500), scale ₹19,999 (unlimited).
  Customer-facing landing at `/for-business`. Verified end-to-end on
  prod with a real PDF + quota increment + cleanup.
- **IndiaCode grounding hardened**: `lib/legal-research/india-code-map.ts`
  ships a curated, live-sourced map of 28 central Acts with real
  `/handle/123456789/<id>` URLs. `groundCasePrepFramework` consults
  this first (no network, no secrets); falls back to the live connector
  for uncovered Acts. UI/PDF show the "IndiaCode" verified badge +
  source link only on matched Acts.
- **Payment fixes**: extracted `lib/payments/finalize.ts`
  (`finalizePaidDocument`) so the Razorpay webhook AND the admin
  UPI-verify route both deliver the PDF/DOCX, fire the lawyer-review
  add-on, and email/WhatsApp the customer. `maybeCreditFirstPaid` now
  fires on both capture paths (was dead code).
- **Cron jobs actually work now**: both `/api/cron/subscriptions` and
  `/api/payouts/release` were broken for Vercel Cron (POST-only on
  payouts, custom `x-cron-secret` header on both). Added
  `lib/cron/auth.ts` (accepts `Authorization: Bearer <CRON_SECRET>`
  which Vercel auto-sends, plus legacy `x-cron-secret` for the e2e
  suite). Payouts now accepts both GET (Cron) and POST (manual).
- **Security**: Next.js bumped `14.2.15 → 14.2.35`. Closes the critical
  CVE class fixed within the 14.2.x line (including CVE-2025-29927
  middleware auth-bypass, CVSS 9.1; not directly exploitable here as
  the app has no middleware) plus several CVSS 7.5 Server-Component
  DoS issues. The residual 4 high CVEs require a major Next 15.5.16+
  upgrade — kept as a separately-validated effort, not a blind bump.
- **OpenAPI + prod-smoke**: `/api/openapi` now advertises the v1
  routes + `apiKeyAuth` Bearer scheme + `b2b` tag (visible in RapiDoc
  at `/api/docs`). `tests/e2e/production-smoke.spec.ts` extended with
  contract assertions for the v1 auth gates and the cron handlers
  (GET handled, never 405; always reject unauth with 403/503).
